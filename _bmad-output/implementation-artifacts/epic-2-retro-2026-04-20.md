## What Went Well

1. **EnemyBase framework paid off immediately** — Beetle Soldier was ~30% new code, the rest was shape + state-machine plumbing. Next enemy will be even cheaper.
2. **Visualization unlocked iteration speed** — floating damage numbers (2.4) and `Magic: N` counter (2.5) turned "I think it works?" into "I can see it works" loops. Debug key-code printer similarly accelerated controller diagnosis.
3. **Party mode review saved a broken design** — Story 2.4's shrinking combo window was mathematically impossible (enemy cycle 170f, window shrunk 120 → 30). Caught before implementation shipped. Refill-on-parry is a better design *and* actually works.
4. **Solo-dev workflow patterns held** — CLAUDE.md updates, memory files, Notion sync, and `park it` discipline kept state coherent across sessions.

## What Didn't

1. **Unverified placeholders bit late** — joypad bindings in `project.godot` had wrong SDL button indices (LB=4 instead of 9, etc.) from Epic 1. Only caught when PS5 controller was plugged in during 2.4 polish.
2. **AI tuning was 4+ iterations on the Beetle** — (a) stood still (missing `is_on_wall()`), (b) never gave up chase (missing disinterest timer), (c) vibrated when squeezed (missing flip cooldown), (d) player could stand on it harmlessly (missing ContactZone). All invisible from code review; required playtest to find.
3. **Secret leak via permission grants** — Notion API bearer token landed in `.claude/settings.local.json` twice when approved Bash commands embedded it literally. GitHub push-protection blocked once; had to reset and recommit.
4. **Mechanic composition broke earlier tuning** — attack hitbox (12×10, 4 frames) worked until dash-jump landed. Composed mechanics changed the viability of static tuning values.
5. **Scope creep vector is creative inspiration, not requirements** — dash-jump was unplanned but landed in a sprint commit. Cool, but worth naming.

## Root Pattern

**Bugs hide in the seams between systems.** Single-system code (throw, parry, save format) worked first try. Multi-system interactions (dash-jump × hitbox, beetle AI × level geometry, combo × enemy cycle timing) all needed iteration under the running game.

## Epic 3 Preview — Improvised Tools & Crafting

**Flagged risk:** Stories 3.2–3.4 each define 3 gameplay mechanics (9 total across thumbtack/penny/yarn). That's denser per story than any Epic 2 work. Epic 2's single-mechanic stories already needed 3–5 iterations. 9 mechanics in 3 tickets is a planning vs. execution mismatch.

**Dependencies on Epic 2 work:**
- Save format needs inventory schema extension
- Input system needs a tool-use button (R2 on PS5 is free)
- Attack system branching (tool vs blade) — spec is unclear
- Enemy damage interface may need richening (stagger, bleed, stick-in)

**Testing concern:** 3 tools × 3 states (held/used/broken) × enemy types × environments = large combinatorial surface. Manual regression will be painful.
